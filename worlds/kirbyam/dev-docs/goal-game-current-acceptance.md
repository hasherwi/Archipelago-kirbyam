# Goal Game acceptance after Phone integration

The protocol-3 patch has now completed all sixteen physical Goal Game source
fixtures, returned to Central Circle and retained each expected isolated Goal
bit in a fresh-process native save reload. The source and patch fingerprints,
controller sequences and private artifact hashes are recorded in
`goal-game-all-sources-successor.json`. The preceding ownership control and
Phone/Goal RAM-overlap regression remain in `goal-game-phone-successor.json`.

These are disclosed native-file-0 fixtures. Each starts with a blank save and a
ROM startup-room/position override near its physical entrance, with Phone
configuration enabled. They do not grant Goal flags or write runtime positions.
The original generic movement missed Moonlight's raised mirror and Peppermint's
left-hand mirror; a short jump followed by landing, and leftward movement,
respectively reached those entrances. No production change was needed.

Additional acceptance is recorded in `goal-game-files-reconnect-successor.json`:
ordinary native file selection completed source0 on files1/2, retained both on
reset, and left file0 unset in the same battery save. A fresh matching seed and
the shipping client/MultiServer reported an offline completion after reconnect.
A second reconnect retained one check and one reward, without duplication.

`goal-game-zero-prize-successor.json` records a completed run with zero native
bonus-collection callback entries. A neutral-input control recorded two entries;
both completed. Read-only instruction stepping and an uninstrumented replay
agreed on every sampled room and saved Goal record. The native collection-handler
code is unchanged from the original ROM. No score or reward flag was injected.

These fixtures establish bounded native behavior, not natural route access or
Normal-only feasibility. Linked-GBA multiplayer and BizHawk GUI behavior remain
unverified. Files1/2 and real reporting use source0, while the complete source
matrix uses file0. Historical evidence retains its original build and scope;
its coverage limits are superseded only by the specific results above.

This evidence-only update does not change the player-facing feature or its
existing changelog entry.
