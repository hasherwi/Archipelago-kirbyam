# Narrow Phone progression admission

This supplements, rather than rewrites, the historical Phone ledgers. The
standard Phone item has **one** profile-qualified cooperation witness: native 146 main
through its Heave-Ho lower-right pocket into 148 upper-left and physical Chalk
collection. It is not permission for helper attacks, Bomb Blocks, copy abilities
or discarded-star sources. The 315/310/426/511 candidates are not admitted by it.

## Qualified profile and resources

Every new seed includes Phone ownership, without an option. The physically
qualified profile is native ability assignment, gating off, HP 6–10, enemy
health 100%, either Room Sanity setting and no One-Hit preset. Its resolved Sir
Kibble source must grant Cutter. Generation and output recheck the installed
profile/source signature so later mutations cannot retain stale qualification.

Other valid profiles generate normally. Their existing 146 main→bottom-right
edge receives only an AND Phone-ownership constraint, preserving prior rules.
This conservatively makes the newly locked R capability available before the
candidate edge and prevents placing Phone solely behind that edge. It does not
prove physical helper cooperation, necessity, sufficiency or universal absence
of softlocks. No fallback source/Hub/Key witness is claimed. Other edges are
unchanged; helper attacks are never added as source capabilities.

The route requires Phone a Friend, Rainbow Route East's Hub Connection,
Moonlight Mansion's Area Key when Area Keys is enabled, and independent access
to the 143 main/source side (`ROOM_1_42`). The finite native Sir Kibble template
`0x088B7C0C` supplies human Cutter for the approach. The human subsequently
loses Cutter and uses Normal for the lower bomb/ladder and cooperative inhale.
The post-tutorial same-file save/reset opportunity restores three batteries;
two calls gather and recall helpers (3→2→1). This reset does not promise to
reroll helpers, erase saved WORLD history or impose universal AI behavior.

The real-hub ungated positive and repeat in `phone-real-hub-evidence.json`
actually reach 148 and collect Chalk, beyond the intermediate script event 15.
`phone-reset-source-evidence.json` and `phone-helper-source-boundaries.json`
retain the resource and helper-history qualifications. Gated/HP 1 successes are
historical corroboration, not additional admitted profiles. Area Keys off only
removes the approach door lock; it adds no helper/source behavior.

## Conservative routing, not physical necessity

On the qualified profile, the 146 main→bottom-right edge is qualified by this
witness while preserving existing constraints. Other profiles receive only the
ownership constraint described above. All other edges, return paths and chest
compartments stay unchanged. No already-qualified solo
witness on that edge is removed. Potential Final Cutter or ambient-helper
bypasses are not declared impossible; they lack a complete admitted source
witness here. No generic Cutter/Sword inventory bypass is invented.

Generated-world tests with all other items reach 143 and 146 but not Chalk;
adding Phone reaches Chalk. Both Area Keys settings are covered. The check
therefore supplies actual progression logic and does not self-lock access to
its human ability source. Separate complete generation/fill tests cover the
item's placement. Pure graph/token tests are not additional physical evidence.

## Room Sanity extension

Room Sanity adds AP visit checks; it does not shuffle rooms or change the
cooperation procedure. `regions.py` materializes additional visit locations,
and `client._poll_room_sanity_locations` reads existing native visit flags and
sends LocationChecks. It does not write helper, pose, battery or ability state.
Production ROM token bytes and Phone intent are identical for on/off with the
same seed identity and otherwise identical supported options. The physical witness remains restricted to its reviewed source/gating/health/enemy
profile; these are not restrictions on generating the Phone item.

Paired on/off tests cover the actual graph, independently reachable source,
Phone-required Chalk collection, token equality and complete generation/fill
with beatability, accessibility and reachable Phone placement. A client test
uses recorded-shaped flag bytes and checks only the AP check-set expansion;
it is not a native gameplay run. More AP checks can change item placement and
receipt timing, so no identical controller schedule or live-server timing is
claimed. The physical witness remains the previously admitted route.

## Live-charge payload successor

The battery successor base patch is SHA256
`c3fca0d4b550130d6ff65e7679aca4950a88ae8d36a036d9371be918f79cd630`.
It changes the payload identity, not the historical ledgers
or their ROM hashes. It masks only the eligible unowned HUD and replaces the
selected charge writers with a task/epoch-bound live uint32 counter. After
ownership, native zero/one/two/full rendering and the reviewed three-charge,
two-call procedure retain their behavior. Additional AP charges can exceed
three (and the native byte range); native pickups, drain and reload/death
refills retain their distinct existing semantics. No persistent surplus bank
or helper-state reset is introduced.

Validation is source/byte-guard and host execution evidence: all 13 hook windows,
actual C lifecycle tests, hostile-callee synthetic ARM register/flag/stack
contracts and client delayed-ACK tests. Rebuilt payload/extension bytes and
existing relocated call targets are distinguished from the 13 added sites.
These checks are not a new physical route run or qualification of fallback
profiles. Historical gameplay evidence remains unchanged.
