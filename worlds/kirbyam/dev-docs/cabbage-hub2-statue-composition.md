# Cabbage Hub2 statues and Chocolate acquisition

The `hub2_statues_entry` witness starts at independently reachable Cabbage Hub2,
native591. It reuses the existing `statues_591` physical source set: original
statues0x088CB010 and0x088CB034, with native Spark and Fighter grants. Their
acquisition from hub-mirror arrivals, permanent retouch and runtime assignments
are already reviewed under `docs/traversal-logic.md#ordinary-hub-statue-network`.
The source set is shared, not reconstructed from item ownership.

This is a composition of reviewed mechanics, not a new uninterrupted replay.
The existing Chocolate witnesses establish the physical591→517 doorway, arrival
at(696,296.996), ordinary movement toward the original Doo compartment, and ten
separately qualified equipped-ability suffixes through chest collection. The
statue route carries equipment across that doorway and ordinary approach; it
does not inhale the Doo or consume its finite instance. Native room travel does
not discard these ten abilities. The existing Mini transition loss remains in
the common engine; Mini is not a Chocolate provider or an allowed statue pool
selection.

Each final edge preserves one existing complete provider-specific suffix:
Beam, Smash, Fire, Missile, Parasol, Spark, Ice, Sword, Fighter or UFO. Their
attack, collision, carry and timed-gate evidence is unchanged. Sharing the
source compartment does not invent a capability for another ability. The ten
finite-Doo routes remain unchanged. Beam now carries an explicit graph-level
raw-grant guard equivalent to its former target-level guard.
The new graph adds a source alternative; it does not erase physical source
access, required permission, equipment loss or the target-specific suffix.

Target applicability now considers the actual Doo and both statue assignments.
When statues are unshuffled, enemy randomness and even100% enemy no-ability
weight do not remove their native Spark/Fighter grants. When statue shuffling
is enabled, SourcePolicy uses the actual runtime table/mask and allowed pool.
Unwanted fixed results cannot be rerolled. Live retouch retains the existing
explicit positive-support fairness assumption and is never described as a
finite guarantee. Unsupported source policies remain unresolved rather than
being declared impossible.

Spark, Fighter, Ice, Missile and Parasol classification uses these actual
installed sources as applicable. Classification checks the enabled chest and
source policy before region creation, so explicit precollection does not lose
permission because a location object has not yet been constructed. Gating off
still needs a physical grant, and a source behind its own barrier cannot supply
initial equipment. RoomSanity, adjacent exits and the paused playthrough are
unchanged.

The common bounded acquisition transfer does not use a temporarily singleton
permission-filtered live pool as a finite guarantee. Runtime grant computation
remains unchanged: permissions can filter current outcomes, but later unlocks
can expand them. Bounded logic requires the full unrestricted outcome set and
no failure outcome; common-capability uncertainty is still preserved. Reviewed
renewable retouch continues to use the actual permitted positive-support pool
with its explicit retry assumption. This keeps finite acquisition conservative
without treating a possible random draw as guaranteed equipment.

The public profile audit leaves statues unshuffled. Its Chocolate fallback
removal therefore describes those profiles, not every shuffled-statue setting.

Harrison's final scope for PR #1116 ends with this Chocolate work. Remaining
unsupported policies and other encounter/action contexts are consolidated in
[v1.0.0 issue #1122](https://github.com/hasherwi/Archipelago-kirbyam/issues/1122).
The shared audit deliberately continues to report incomplete overall coverage.
